## Approved input

The operator activated the v1 execution policy on 2026-10-09. The coordinator
assigned one implementation writer on `codex/v1-p01-runtime`, starting at
`e4d7b84f6293490ffca9265ce0b87d2e45f110ac`. Remote was verified as

Astra medium approved the complete revised P01 plan, SHA-256
`07278b67c601f931b2972f86566fec3c388db4b1aa85eb34b310105de8f3d912`, on
2026-10-09. Its revised verdict superseded four initial blockers. The accepted
plan requires same-site private-read rejection, lock-last shutdown, one atomic
credential-set file, and a nonserializable same-process owner guard against plain
`next start`. The implementation preserves those boundaries. The approval is a
plan gate, not an implementation verdict.

The plan selects a single custom Next HTTP process over a launcher/child layout.
A retained SQLite `BEGIN EXCLUSIVE` transaction on a separate stable lock file
owns the directory. The HTTP envelope validates Host, Origin, body size/time and
private-page access before Next dispatch. Next boundaries repeat ownership and
session guards. Application connections require live ownership and register with
it. Shutdown rejects new work, closes the listener, drains handler promises and
asynchronous backups, closes Next and application connections, then releases the
lock. No PID diagnostic file is retained or used as authority.

Filesystem checks reject symlinks, wrong ownership, nonregular sensitive files,
and group/other permissions. New directories/files use 0700/0600. Credentials
have distinct random 256-bit pairing/reporter values in a protected versioned
`credentials.json`. Sessions store SHA-256 hashes, an operator principal and
12-hour expiry. Rotation is stopped-service, revokes sessions durably before
atomic publication, and discards unpublished staged files after interruption.

SQLite uses WAL, FULL synchronization, foreign keys and a 250 ms busy timeout.
Reviewed SQL and checksum history migrate in one transaction. Existing databases
are integrity-backed up before pending migrations. Failed migrations preserve
rows and roll back schema/history. Restore validates a SQLite backup, stages a
new generation without sessions, preserves the damaged database/WAL/SHM bundle,
and atomically replaces the main database. Its durable marker fails closed after
interruption; `local restore repair` completes the recorded operation.

The shipped UI is pairing plus authenticated storage readiness. It uses the
approved offline system font, neutral canvas and blue action style. It carries no
external assets or analytics. Framework telemetry is disabled. The only shipped
API routes are health, session and authenticated foundation readiness.

## Implementation method

Poteto Feature and the implementation skill govern this package. Model the
Domain shaped principal/runtime unions. Boundary Discipline put input parsing at
HTTP, CLI and filesystem entry points. Sequence Work into Verifiable Units shaped
the small Conventional Commits. Prove It Works required real SQLite files, a built
Next server, subprocess interruption and a real browser. Parallel design was
already settled by the approved plan. Nested writers/reviewers were excluded by
the coordinator; independent review is a separate parent-owned lane.

The throughput checkpoint serialized the coupled runtime/storage/auth writes in
one worktree and gave each subprocess a fresh directory/port. Dependency install
and the native-loading gate ran before production proof. Review remains separate
from the sole writer. No shared operator database was used.

Initial storage/policy tests were authored before their code but could not execute
until Vitest installed. Do not treat that as executed behavioral red evidence.
The pre-implementation recovery import failure is retained separately. Later
actual regression red/green pairs prove empty-cookie/bearer ambiguity, safe errors
for malformed credential JSON, refusal to release an owner with open connections,
refusal to close storage during asynchronous backup, and the reviewed GET/HEAD
body-limit bypass. Red logs show failed
assertions before the fixes; green logs show their passing results. The log-print
shell wrappers were not used as test-success evidence.

## Dependency findings and limits

`npm audit --omit=dev` reports zero findings. Full audit reports nine affected
package entries from two dev-tool advisories, five high and four moderate.
There is no blanket audit waiver or forced downgrade.

- `braces <=3.0.3` has recursive-pattern stack exhaustion. Its
  [reported upstream issue](https://github.com/micromatch/braces/issues/70) and
  [reviewed advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) list no
  patched release. The affected chain is braces → micromatch → fast-glob → Next
  ESLint plugin/config. P01 lint uses trusted local source paths; HTTP input does
  not reach that dev-only glob parser. Do not run lint with hostile glob patterns.
- Nested `esbuild 0.18.20` is reached through DrizzleKit's esm-loader/core-utils.
  The [maintainer advisory](https://github.com/evanw/esbuild/security/advisories/GHSA-67mh-4wv8-2f99)
  concerns esbuild's serve API, affected through 0.24.2 and fixed from 0.25.0.
  P01 does not call that serve API. Next owns development/production HTTP with
  the local security envelope. The parent package's supported dependency range
  does not admit that fix; overriding a major version or npm's suggested major
  downgrades has not been qualified. Avoid esbuild serve through that old tool.

ESLint 9.39.4 is marked unsupported by the registry but passes this pinned Next
configuration. Revisit the supported dev-tool combination before a future
upgrade; P01 retains the approved working pins. `skipLibCheck` excludes upstream
declaration errors in Drizzle's unrelated optional drivers and Next URLPattern
ambient types, while strict application type checking remains enabled.

Only the named macOS host and Chrome channel are qualified. Network filesystems
are unsupported without reliable portable detection. Symlink parent aliases are
rejected; tests use canonical temporary paths. Real operator data, live provider
credentials, human attestations, release publication and downstream package
behavior are outside this receipt. The next gate is independent standards/spec
review of the exact final candidate and coordinator verification before merge.
