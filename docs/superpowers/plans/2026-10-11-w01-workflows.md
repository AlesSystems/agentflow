## Global constraints

- AgentFlow observes externally started work. No launch, stop, shell, scheduler, provider-private-state access or automatic task completion.
- Keep `/api/v1`, UUID identifiers, camelCase, UTC timestamps, strict schemas, 64 KiB requests, no-store replies and current generation headers.
- One project per workflow; immutable increasing plan revisions, maximum 100 nodes and 200 edges. Node IDs are UUIDs stable within the workflow; labels are bounded to 200 characters. Reject missing endpoints, duplicate node IDs/source-target edge pairs, self edges, cycles and cross-project links atomically.
- Only one queued/running workflow attempt per workflow. A run binds one immutable revision; publishing a later revision cannot retarget it. Give workflow attempts a separate durable non-reusing registration order; leave the task-attempt allocator unchanged.
- Reports have event ID, workflowRunId, sequence starting at 1, schemaVersion 1, occurrence time and typed payload. Exact retries resolve before mutable checks; changed bodies/reused sequences/gaps write nothing.
- Queued start becomes running; node reports and heartbeat require running; success/failure/cancellation are terminal, with queued cancellation allowed. Human stale close records interrupted and never stops an external process.
- Missing nodes/skill fields remain Unknown, including terminal workflows. `reportedSkill` is inert `{name, source?, version?}` bounded to 200/2000/200 characters, never fetched or executed.
- Workflow freshness, linked-attempt freshness and browser connection are independent. Active silence over 60 seconds is stale observation; use the shared visible 15-second refresh.
- No W02 dependency/review/rework gates, W03 integrations/retention/usage, or release work in this package.

## Review focus

1. Colliding task/workflow producer UUIDs cannot share a sequence, cursor, ACK or spool directory; Task 3 tests both kinds together.
2. Old revision/attempt observations retain their original task/run links after a new plan; Tasks 1–2 test revision immutability and successive links.
3. Exact retry after terminal state, archive or restore resolves stored identity before newer mutable checks; Tasks 2–3 exercise real lost responses and generations.
4. Malicious skill text, oversized valid-shape plans and nested path parameters cannot bypass auth, body bounds or reference validation; Tasks 1, 2 and 4 pin these cases.
5. Refresh, wrong-node reports, graph/list toggles and narrow/zoom views cannot steal focus or confirm an unseen report; Task 4 uses actual browser identity and visibility controls.
