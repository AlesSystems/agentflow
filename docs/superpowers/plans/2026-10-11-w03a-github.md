## Current official contract and choices

Verified official GitHub documentation on 2026-10-11:

- [API versions](https://docs.github.com/en/rest/about-the-rest-api/api-versions?apiVersion=2026-03-10) supports `2026-03-10`; pin that explicit header rather than the older unversioned default.
- [PR endpoints](https://docs.github.com/en/rest/pulls/pulls?apiVersion=2026-03-10) supplies list/get metadata. Use only GET on `api.github.com`, `Accept: application/vnd.github+json`, and the pinned version. A selected-repository fine-grained token needs Pull requests read permission; public resources support anonymous reads, but this implementation uses the configured credential path consistently and never silently falls back after authentication failure.
- [Rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) and [best practices](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api) require respecting Retry-After and reset/remaining headers. Make requests serially. No remote polling. Reject redirects rather than forwarding a bearer to a different repository or host; an operator can select the renamed repository explicitly.

REST responses contain additional GitHub fields. Parse a bounded response and project only number, canonical URL, title, state, draft, head SHA, base branch, merged time and local fetch time. Never store, expose or log body, diff, comments, user/author/profile or arbitrary upstream error text. Reject invalid identity/shape without publishing partial malformed rows.

## Commands and observation semantics

- Human-only `GET /connections/github` returns connection metadata and bounded cached pages/optional exact PR lookup, with generation/cursor. Page size20, maximum100, stable indexed order. GET/focus/navigation/SSE revalidation always stays local and never fetches GitHub.
- Human-only `PUT /connections/github/repositories` uses normal expectedVersion/key/digest receipts. Body contains enabled and the exact replacement allowlist; no secret or credential path. Disconnect means disabled, preserving cached observations with a disconnected/stale label. Reject reporter use before receipt lookup and do not mutate on conflicts.
- Human-only `POST /connections/github/refresh` is a bounded synchronous browser command with asynchronous I/O internally. Select exactly one allowlisted repository and either one list page or one PR number. One remote GET per command, list page size20, page number bounded1–1000. This avoids an unbounded all-repository scan and gives an older linked PR an explicit number lookup. Validated GitHub Link metadata can supply a next-page hint; never follow a raw Link URL or fetch an unapproved target. UI provides explicit page/number selection.
- Admit operator/receipt/key/body/version/enabled/scope/rate checks in a short transaction. Reserve the durable intent, then snapshot generation/selection. Concurrent identical requests share the same in-flight result; conflicting body reuse rejects before I/O. Allow only one active remote refresh per runtime; a different busy request rejects without a receipt or network. Configuration changes cancel/supersede the old observation; finalization rechecks generation, version and allowlist before any cache publication.
- Fetch outside SQLite, with8-second header/body deadline, maximum2MiB, manual redirects and streaming cancellation/drain on limit/abort. Respect safe Retry-After/reset headers and persist a bounded retry-not-before time. No sleeping/retrying automatically; a subsequent human command observes the rate gate. Credential failure, timeout, invalid payload, rate limit, inaccessible PR and upstream failure yield fixed safe codes with prior data retained.
- Finalize cache/error/result and original successful local-command receipt together in a short immediate transaction. An external fetch failure is an observed local command result, not a failed task mutation. Completed exact retry returns the same result without new network. If a process dies after admission, startup resolves pending intents as interrupted local results without auto-fetching; generation/configuration changes never publish old results. Test original reply-loss and interrupted retry explicitly.
- Runtime closing rejects new admissions, aborts in-flight fetches and drains/finalizes before the existing store closes. Restore/restart keep prior observations labeled; a secret file or PR state never completes, reopens or edits a task.
- A changed observed head retains the previous differing SHA and a head-change stale indicator. The UI marks previously displayed PR-head observations/head-linked external evidence stale. Opaque W02 artifact references are not guessed as SHAs and local review applicability/acceptance never changes. Show fetched time and retain prior fields on offline/disconnect; do not call a404 proof of deletion. Metadata older than5minutes or with failed/disconnected/head-change state is labeled stale, without remote polling.

## Credential boundary

Local setup supplies an optional absolute `AGENTFLOW_GITHUB_TOKEN_FILE` path to a user-only JSON file outside the active checkout. Validate components and opened descriptor with O_NOFOLLOW/O_NONBLOCK, ownership, regular-file type, mode0600, single link and a4096-byte limit before bounded UTF-8/strict JSON parsing. Accept a bounded opaque non-whitespace token without assuming an evolving GitHub prefix. No token/value in command input, shell history instructions, URLs, logs, UI, SQLite, receipts, backups or export. Public metadata exposes configured/unavailable/repair state only, never the file path. Read the file only for an admitted explicit refresh; disabled mode and unauthorized requests cause zero outbound access. Keep transport/parser/file errors redacted at the source, without raw exception causes.

Fixture dependency injection is a trusted server-construction transport seam. Production uses the fixed GitHub origin; no production environment or browser override can authorize another host. Loopback fixtures translate the approved logical GET into an owned responder and record synthetic headers only. No live test may use an unselected repository or repurpose broad delivery credentials implicitly. If no previously approved read-only connection/credential exists, complete deterministic coverage and disclose live credential verification as unexecuted.
