# W03b history implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. The operator selected autonomous agentic execution with independent review. Root supplies the exact-plan Astra medium gate before any implementation.

**Goal:** Let the paired operator download selected history from one coherent snapshot and explicitly prune a bounded set of safely obsolete display payloads, while preserving every identity, receipt, and protected evidence fact.

**Architecture:** Extend the existing Store with narrow history capabilities. One small runtime history owner coordinates private export snapshots and asynchronous pre-prune backup, while database code owns eligibility, previews, transactions, and receipts. Reuse native response lifecycle handling and the existing Workspace subscription, generation recovery, and frozen command intents.

**Tech stack:** Committed Node 24.15.0, npm 11.12.1, TypeScript, Next.js, better-sqlite3, Drizzle, Zod, React, Vitest, and Playwright Chrome. Use the existing exact lockfile. Add no dependency.

**Spec:** [W03b contract](../../V1_WORKFLOWS.md#w03b-export-and-conservative-retention), [PLAN](../../../PLAN.md), [execution policy](../../EXECUTION_POLICY.md), [API](../../API.md), [backend](../../BACKEND.md), [architecture](../../ARCHITECTURE.md), [decisions](../../DECISIONS.md), and [design](../../../DESIGN.md).

## Global constraints

- Default: retain all history. No automatic pruning, task hard deletion, import, export resume, upload, process control, or new background polling.
- Browser-only preview and prune. Export requires a paired browser too because it may include private GitHub observations. Authenticate and enforce actor authority before receipt lookup, including exact retries.
- Preserve tasks, completions, dependencies, revisions, decisions, artifacts, run terminal evidence, event IDs/sequences/digests, and original acknowledgement and request receipts indefinitely.
- No active-run payload, current acceptance evidence, or graph reference is pruned. If safe eligibility is uncertain, retain the record.
- Prune commits removals and a new stream generation atomically. Keep sessions valid here. Restore still invalidates them.
- Every authenticated response carries the current `AgentFlow-Generation`; historical receipt bodies retain their original generation and cursor. Mutation replies do not advance subscription cursors.
- Preserve migrations 0000–0008 byte-for-byte, durable registration orders, event-family collision checks, existing outbox formats, the W02 acceptance predicate, and W03a's connection-wide SQL rate deadline.
- SQLite remains local with WAL, synchronous FULL, and the existing 250 ms busy timeout. No network or file-copy await occurs inside a live database transaction.
- Destructive tests use synthetic, independently owned directories only. This run does not authorize pruning the operator's history.
- Snapshot p95 <250 ms. Explain any genuinely changed existing-operation regression >20 % and obtain Astra approval before delivery. W04 owns the full 1,000-task/10,000-event combined-load and release gates.

## Review focus

1. A command authenticated before prune but completed afterward must return the current header, including historical replay and error responses. Task 3 pins delayed parsing and delayed GitHub completion.
2. A preview may become unsafe while backup runs. Task 2 pins a newly protected candidate, expiry, generation change, and backup failure before the destructive transaction.
3. A blocked SSE connection may hold old frames at prune. Task 3 proves finite reset or the existing bounded disconnect, then snapshot recovery without session repair or lost drafts.
4. A CLI restart may resend a committed event with a lost ACK. Task 3 proves original ACK recovery for both producer kinds, one watermark advance, and no duplicate event.
5. Export may be aborted during snapshot creation, batching, or stalled writes. Task 1 proves no leaked copy/descriptor/lease, a finite failure, and no claim that a partial download is complete.

### Export selected records from the copy

`GET /api/v1/export?content=tasks,attempts,workflows,github&generation=UUID` takes a required nonempty, duplicate-free subset of the four named groups, in canonical order. Unknown fields, repeated query keys, unsupported group names, a cursor, and stale generation fail before a snapshot is created. `HEAD` validates/authenticates without making a copy. There is no continuation or resume token.

Use a versioned JSONL protocol. First line is `{kind:"manifest",schemaVersion:1,generation,snapshotCursor,createdAt,content,counts}`. Record lines are `{kind:<fixed record kind>,data:<explicit projection>}`. Last line is `{kind:"complete",schemaVersion:1,counts}` only after every record was written. `counts` contains exact per-kind counts for the selected groups. Missing completion means interrupted export. Document omitted groups and cross-group references as intentionally incomplete selections, not restorable backups.

- `tasks` includes projects, tasks, agents, comments, completions, reopens, dependencies, policies on tasks, artifacts, gate decisions, rework, and human run/workflow closure facts.
- `attempts` includes task runs and task event history, including retained stubs.
- `workflows` includes workflow identities, immutable plan revisions/nodes/edges, workflow runs, events, and node observations.
- `github` includes the safe persisted connection configuration and projected PR observations. Do not read credentials or contact GitHub.

The following mapping pins each record kind and its source. Use UTC ISO timestamps, parsed JSON arrays/objects, and strict existing public schemas for listed projections. Emit one row per source row; no SELECT * or raw envelope/receipt spread. Stable paging uses each table’s indexed primary key, except events use parent ID/sequence and revisions use workflow ID/revision. Counts come from these same source tables in the completed copy.

| Group / record kind | Source and explicit projection |
| --- | --- |
| tasks / project | `projects` through `project.omit({repositoryPath:true})`. Fields are id, name, archivedAt, version, createdAt, updatedAt. |
| tasks / task | `tasks` through the stored `task` schema, not taskSnapshot joined readiness. Its existing editable fields, id/projectId/status/version/workRevision/policies/reworkRound/timestamps are preserved. |
| tasks / agent | `agents` through `agent` schema. No derived liveness or local process identity. |
| tasks / comment, completion, reopen | `comments`, `completions`, `reopens` through corresponding existing schemas in `tasks.ts`. |
| tasks / dependency | `task_dependencies` with taskId, prerequisiteId, projectId. |
| tasks / artifact, decision, rework | `task_artifacts`, `gate_decisions`, `task_reworks` through `artifactEvidence`, `gateDecision`, `reworkEvidence` in `evidence.ts`. Opaque artifactRef is retained unchanged, including values that look like a path. Never infer or open it. |
| tasks / runClosure, workflowClosure | `run_closures`, `workflow_closures` with id, runId or workflowRunId, reason, actor, createdAt. |
| attempts / run | `runs` through `run` in `tasks.ts`, excluding internal registrationOrder. Include the existing artifactRef and reworkRound fields without inferring their meaning. |
| attempts / runEvent | `run_events` through intact-or-stub `eventRecord`. Do not include digest or acknowledgement transport columns. They remain retained in SQLite and recovery backups. |
| workflows / workflow, revision, workflowRun, workflowEvent | `workflows`, `workflow_revisions`, `workflow_runs`, `workflow_events` through `workflow`, `planRevision`, `workflowRun`, `workflowEventRecord`. Revision nodes/edges are arrays inside each revision row, not invented separate tables. Exclude internal digest/body/registrationOrder/ACK fields. |
| workflows / nodeObservation | `workflow_node_observations` through `nodeObservation`; include that accepted typed report and received time only. |
| github / connection | `github_connection` with enabled, repositories, version, lastAttemptedAt, lastFetchedAt, lastError, retryNotBefore. Exclude synthetic runtime credential/busy fields. |
| github / pullRequest | `github_pull_requests` with repository, number, url, title, state, draft, headSha, baseBranch, mergedAt, previousHeadSha, fetchedAt, lastAttemptedAt, lastError. No derived source-external claim. |
| github / lookupAttempt | `github_lookup_attempts` with repository, number, attemptedAt, error. |

Exclude every other table, including settings, sessions, changes, receipts, run/workflow registrations/identity ledgers, allocators, GitHub refresh intents, retention previews/state, and instance metadata beyond the manifest. This download is selected business history. These export omissions never authorize deletion of their durable ledgers. All request receipts and original ACKs remain indefinitely in the application and its private backups for exact replay.

Write an explicit typed field allowlist per record kind. Exclude sessions, credential values/files, connection secrets, all filesystem path fields including project repository paths and settings data location, runtime lock metadata, pending transport intents, and original transport request-receipt bodies. This is content export, not backup/restore. Do not claim arbitrary operator-authored text is secret-free. Preserve selected user text and inert URLs without opening them; inject credential/path sentinel values into excluded structured fields to prove exclusion.

Use `Store.backup(destination)` in a unique mode0700 export directory outside the checkout with mode0600 files. Its return metadata is live and unsuitable for manifest identity. Open the completed copy read-only and obtain manifest generation/schema/cursor/counts from that copy. Capture `createdAt` once after the copy succeeds. Extend `Store.backup(destination:string,signal?:AbortSignal)` only with optional cancellation, retaining the existing 100-page transfer default and all integrity/fsync/work tracking. The pinned [better-sqlite3 13.0.3 backup API](https://raw.githubusercontent.com/WiseLibs/better-sqlite3/v13.0.3/docs/api.md) aborts when its progress callback throws. Use that callback to observe the history lifetime signal, await backup settlement, then clean the owned partial copy. Existing callers without a signal retain their behavior. No backup copy is exposed through HTTP. Iterate stable indexed keys in batches of at most 100 rows, releasing each copy query before writing. Keep at most one batch and at most 1 MiB pending native output; pause on Node backpressure. A blocked output closes within 5 seconds, and an export has a 5-minute overall lifetime. Admit at most 2 exports per runtime, returning 429 for another. Before headers, copy/integrity failure is a fixed safe503; after headers, terminate without a completion line. Abort and shutdown cancel copy work through the optional backup signal, await its settlement, close the reader/descriptor, and remove only that export’s private files/directory. Use a dedicated `exports` parent under the owned data directory and exact generated child ownership guards. Startup may remove abandoned export children only after acquiring the existing instance lock and verifying their expected owner/type/private mode; retain uncertain paths rather than deleting them. No recursive arbitrary-path cleanup is introduced. Concurrent writes or prune may advance live metadata, but a completed export remains exactly one copy and the current header is sampled when headers are sent.

### Preview a bounded, conservative candidate set

Add a separate singleton `retention_state(version=1)` and immutable issued preview records. Keep retention versions independent of timezone and GitHub configuration versions. Add nullable `payload_pruned_at` to `run_events`. Preserve its whole accepted-envelope `body` when unpruned. At prune, replace only the accepted envelope’s `payload` with JSON null using `json_set(body,'$.payload',NULL)` and timestamp it. Keep body NOT NULL and its existing json_valid CHECK. Do not overwrite it with `{}` or invent an original empty payload. Migration 0009 replaces the blanket `run_events_no_update` trigger with a narrow guard that allows only this first irreversible payload transition. It requires every identity/sequence/type/digest/ACK/occurred/received field unchanged, the exact expected body transform, an eligible terminal parent, and no protected reference. Keep all other event updates and deletions forbidden. Add direct-SQL regressions for replacement/identity/ACK/digest mutation, repeat timestamp update, payload restoration, terminal/protected bypass, malformed marked insert and rollback. New insert guards require unpruned accepted input; SQL NULL comparisons must use explicit null-safe equality so a NULL mutation cannot bypass the trigger. Preserve the prior SQL bytes while adding this reviewed replacement. Add an additive read-only stub union with schemaVersion 1, eventId, runId, sequence, original type, occurredAt, receivedAt, `payload:null`, and nonnull `payloadPrunedAt`; intact existing event shapes remain unchanged.

Candidates are received strictly before the explicit cutoff. Eligible task events are only `run.progress` or `run.heartbeat`, unpruned, with a terminal parent (`succeeded|failed|cancelled|interrupted`). Conservatively exclude the whole parent run if any completion's implementation_run_id, artifact's run_id, gate decision's run_id/event_id, or workflow node observation's run_id references it. Keep all workflow event bodies, especially node reports and heartbeat records, in this package. Keep all task run identity/projections, terminal events, closures, registration ledgers and allocators. This conservative subset satisfies safe eligibility without inventing a graph-reference weakening.

Obsolete changes are rows with received_at strictly before cutoff, excluding the newest row. Keep `sqlite_sequence` for changes. A successful prune inserts one new generic retention invalidation after deletion in the same transaction, so snapshot max cursor advances beyond the original high-water even if almost every old row was eligible. Never reset or rebuild the change allocator. Old-generation subscriptions must reset before using retained numeric gaps.

Each preview includes at most 1,000 task-event candidates and 1,000 change rows, in stable receipt-time/identity and cursor order respectively. Read at most 1,001 to produce per-kind `hasMore`; the preview promises the exact bounded candidates, not an all-history count. Additional batches require another preview. A canonical SHA256 binds the cutoff, generation, retention version, selected ordered candidate identities, original digests/types/receive times, and current protection eligibility. Candidates arriving or becoming protected before confirm change that digest or eligibility and require another preview. Never trust client-supplied candidate IDs or row counts.

`POST /retention/preview` accepts `{cutoff}` only, strict UTC ISO datetime with `Z`, valid Date range, no future time. It requires the normal idempotency key and stores its original response. Response data is `{previewId,cutoff,expiresAt,expectedGeneration,expectedVersion,candidateDigest,counts:{eventPayloads,changes},hasMore:{eventPayloads,changes}}`. Expiry is 5 minutes from issue. Missing/expired preview returns 409 `preview_expired`; changed generation/version/candidates returns 409 `preview_changed`. An exact preview retry returns its original result even after expiry; this does not authorize a later prune. Cap unresolved unexpired previews at 20 per operator and return429 rather than accumulate unlimited ephemeral records; remove expired unconsumed preview rows during a subsequent preview admission, preserving request receipts.

`POST /retention/prune` accepts exactly `{previewId,expectedGeneration,expectedVersion,candidateDigest}` and a normal idempotency key. Authenticate the operator, validate, then recover an existing original receipt before expiry/current-state checks. Admit only one in-flight prune per runtime. Concurrent exact requests share the result; a changed body conflicts, and another key returns 409 `retention_busy` without consuming it. No durable async job framework is needed because prune has no asynchronous remote effect. A crash before transaction means unchanged history and safe fresh admission on restart. A crash after commit means replay the original receipt.

Check preview guard before backup. Make and integrity-check a uniquely named local recovery backup through the existing Store facility, then recheck time, generation, version, candidate digest, and protection inside the final immediate transaction. Backup failure, abort/shutdown before commit, or a failed guard changes no history/generation/session/version/receipt. Preserve a completed recovery backup after failed finalization; report it as a local backup, not successful prune. Backups remain owner-only outside the checkout. No path is exported or included in public prune DTOs. A shared in-flight prune abort before transaction cancels all current waiters safely; they may submit the same unconsumed intent later. After commit, caller loss cannot cancel the mutation, and exact retry recovers its original receipt. Never delete a completed recovery backup because an HTTP response was lost. A successful original response includes previewId, applied counts, prunedAt, prior/new generation, retention version, and measured display-body bytes removed. SQLite database/WAL sizes are separate observational before/after samples; do not promise reclaimed disk blocks or run VACUUM.

Commit body removals, change deletion, generation-only renewal, version increment, generic invalidation, and original receipt together. Generate the UUID inside this transaction; rollback preserves all earlier facts and sessions. Do not call existing `renewGeneration()`, which correctly revokes sessions for restore. Exact retry makes no new backup, generation, invalidation, timestamp, or write.
