# W03c Reported Usage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. Independent task reviewers precede the next task.

**Goal:** Show durable reported token deltas, honest coverage, and optional local price estimates without inflating retries or implying complete billing.

**Architecture:** Extend the existing ordered run-event transaction with an immutable usage ledger. Read bounded coherent snapshots through the existing Store/API/client owner; use exact BigInt aggregation and immutable local price snapshots. Preserve history export, retention, authentication, and the external-harness observer boundary.

**Tech Stack:** Existing Node 24.15.0, npm 11.12.1, TypeScript, better-sqlite3 13.0.3, Zod, Next.js, React Query, Vitest, and Playwright. No new dependency.

**Spec:** [PLAN.md](../../../PLAN.md), [execution policy](../../EXECUTION_POLICY.md), [Phase 3 contract](../../V1_WORKFLOWS.md), [API](../../API.md), [backend](../../BACKEND.md), and [DESIGN.md](../../../DESIGN.md).

## Review Focus

1. Two fresh envelopes reuse one usageId with changed nullable counts or billing basis; reject transactionally without consuming a sequence or altering the first fact (Task 1).
2. An upgrade encounters existing gate-decision FKs and an already-pruned progress row, then faults after DROP; retain exact old data and restore foreign-key enforcement (Task 1).
3. Many individually valid counts overflow SQLite SUM or JavaScript Number; return exact decimal subtotals and money without truncated groups changing overall totals (Task 2).
4. Producer measurement falls inside the interval but first receipt falls outside, or a duplicate receipt falls inside; interval membership stays tied to the first accepted receipt (Tasks 2–3).
5. A browser holds an old page cursor and unsaved price/filter drafts during prune, restore, or lost replies; refresh coherent snapshots, preserve drafts, and require explicit retry (Task 4).

Shared types are inferred from strict Zod schemas. `UsagePayload` has usageId/source/model strings of 1–200
characters, canonical UTC `measuredAt`, required nullable inputTokens/outputTokens, and optional nullable
`billingBasis: 'input_output_only' | null` normalized to null.
`UsageQuery` has projectId, canonical UTC from/to, optional exact source/model and priceSnapshotId, limit 1–100
default 50, and optional bound cursor. Positive interval duration is at most 31 × 24 hours.
`UsageData.accept(runId: string, eventId: string, payload: UsagePayload, receivedAt: number): void` runs inside the
caller's event transaction after valid fresh-sequence/running checks and after the parent event is inserted.
`UsageData.snapshot(input: UsageQuery, now: number): UsageSummary` runs inside the existing read snapshot.
`UsageData.createPriceSnapshot(input: PriceSnapshotCreate, context: CommandContext): CommittedReply` uses the
existing command/receipt transaction. `UsageData.priceSnapshots(input: PageQuery): PriceSnapshotPage` uses existing
bounded keyset semantics.
`UsageSummary` contains interval/filter provenance, project-wide eligibleRuns/runsWithReports/runsWithoutReports,
filteredReportCount, filteredRunsWithReports, knownInputTokens/knownOutputTokens/knownTotalTokens decimal strings,
unknownInputReports/unknownOutputReports/unknownTotalReports, groups/totalGroups/groupsTruncated,
runDetails/totalRuns/nextCursor, and nullable estimate.
Group and run detail totals use the same exact-count/unknown-count shape. Run detail includes
firstReceivedAt/lastReceivedAt and producer measurement bounds with separately labeled meanings, not an unbounded
measurement array.
Run details cover the project-wide eligible set and expose matchingReportCount separately under filters. Overall filtered totals include every selected ledger fact; eligible coverage never borrows a current agent model label.
`UsageEstimate` contains the selected immutable price snapshot, includedReports,
excludedUnknownCounts/excludedUnsupportedBasis/excludedMissingPrice, and exact amount strings grouped by currency.
Snapshot envelopes retain generation and snapshotCursor.
